## Tổng quan dự án

Một hệ thống giám sát nhà thông minh dùng AI. Đích đến: engine C trên NVIDIA DeepStream đọc nhiều nguồn video (file
MP4, luồng RTSP) trong một pipeline batch, phát hiện + tracking người bằng YOLOv8, đổi thành sự kiện `PERSON_DETECTED`
rồi giao cho backend (FastAPI) lưu và gửi Telegram. Hiện tại repo có hai phần: `engine/` (C, đang làm) và các khối
Python giữ lại cho backend sau này (đặc tả `EventManager`, `TelegramNotifier`, `SnapshotCleaner`, config, logging).
Đường CLI Python cũ (Ultralytics + OpenCV, `main.py`) đã bị xóa. `backend/` (FastAPI + PostgreSQL) đã có API camera/event và endpoint nhận event; chưa có frontend.

## Các lệnh thường dùng

Cài đặt Python:
```bash
pip install -r requirements.txt
cp .env.example .env   # sau đó điền TELEGRAM_BOT_TOKEN / TELEGRAM_CHAT_ID, v.v.
```

Chạy backend (sau khi tạo role/database PostgreSQL và đặt `DATABASE_URL` trong `.env`, xem README mục Backend) và engine manager:
```bash
alembic -c backend/alembic.ini upgrade head
uvicorn backend.main:create_app --factory --port 8000
uvicorn engine_manager.service:create_app --factory --host 127.0.0.1 --port 8100
```

Chạy unit test Python (pytest, cấu hình trong `pytest.ini` với `pythonpath = .`):
```bash
pytest                                                    # chạy toàn bộ test trong tests/
pytest tests/test_person_detected_event_manager.py -v     # chỉ test của event manager
```
Test hiện có (221 test, trong đó 149 test backend ở `tests/backend_api/` cần chương trình server PostgreSQL cài sẵn, thiếu thì bị skip, và 21 test engine manager ở `tests/engine_manager_tests/`): `PersonDetectedEventManager`, 17 test chạy vector chung `tests/vectors/event_manager_*.json` và `src/config/env_file.py` (chỉ dùng file `.env` tạm, không
đụng `.env` thật). Không cần camera/model/mạng/màn hình. Ngoài ra có một script kiểm tra thủ công:
```bash
python scripts/test_telegram_snapshot.py   # ghi một snapshot giả và thử gửi qua Telegram
```

Engine C (build trong DeepStream container, test thuần C trên host):
```bash
python engine/tools/export_yolov8_onnx.py   # trên host: yolov8n.pt -> engine/models/yolov8n.onnx (một lần)
cd engine && make CUDA_VER=12.6 && make -C parser CUDA_VER=12.6   # trong container -> build/ds_engine, build/libnvds_yolov8_parser.so
./build/ds_engine --config configs/pgie_yolov8n.txt --tracker-config configs/tracker_nvdcf.yml --camera 1=file:///a.mp4 --camera 2=file:///b.mp4
# thêm --output build/out.mp4 để ghi video lưới có bbox + track ID (debug); --fps-interval SEC đặt chu kỳ in FPS (0 = tắt)
cd engine && make test-core            # trên host, bằng gcc + ASan/UBSan, không cần GPU
```
Mã thoát của `ds_engine`: 0 mọi nguồn EOS hoặc dừng bằng SIGINT/SIGTERM, 1 lỗi pipeline, 2 sai tham số, 3 không dựng được pipeline.

## Kiến trúc

Mã Python còn lại (không có chương trình Python nào chạy pipeline video):
- `src/events/person_detected.py` — `PersonDetectedEventManager` là state machine chống trùng lặp sự kiện: nó lưu
  `last_seen` theo từng `track_id` và chỉ phát `PersonDetectedEvent` mới khi một `track_id` xuất hiện lần đầu hoặc đã
  vắng mặt lâu hơn `absence_timeout` giây (thời gian `now` do người gọi truyền vào). Các track cũ không còn active bị
  dọn sau mỗi lần gọi. Logic thuần túy, không có I/O. Đây là **đặc tả chuẩn** để port sang C.
- `src/notifications/telegram_notifier.py` — `TelegramNotifier` gọi trực tiếp Telegram Bot API qua `requests`
  (`sendMessage` / `sendPhoto`). An toàn khi khởi tạo kể cả lúc chưa cấu hình — chỉ đặt `self.enabled = False` và mọi
  phương thức gửi trở thành no-op, trả về `False`. Không bao giờ raise; bắt `RequestException`/`OSError` rồi log lại.
- `src/snapshot_management.py` — `SnapshotCleaner(retention_days)`: `cleanup(snapshot_dir)` xoá các file
  `PERSON_DETECTED_*.jpg` cũ hơn `retention_days`. Lỗi xoá file được bắt và log.
- `src/config/__init__.py` — nguồn cấu hình duy nhất lấy từ biến môi trường (tải `.env` qua `python-dotenv` nếu có):
  các hằng số đã định kiểu như `ABSENCE_TIMEOUT`, `ENABLE_TELEGRAM`, `ENABLE_SNAPSHOT`, `SNAPSHOT_DIR`,
  `SNAPSHOT_RETENTION_DAYS`, `SNAPSHOT_CLEANUP_INTERVAL`, `LOG_*`, token/chat id của Telegram. Module khác import giá
  trị từ đây thay vì đọc `os.environ`.
- `src/config/env_file.py` — `read_env_values` / `write_env_values` / `is_truthy`: đọc và sửa `.env` in-place (giữ
  comment và key khác, ghi qua file tạm quyền 0600 vì `.env` chứa token).
- `src/logging_config.py` — `setup_logging()` cấu hình root logger một lần (terminal + `RotatingFileHandler` ở
  `LOG_FILE`; nếu tạo file log thất bại thì chỉ log ra terminal). Backend gọi nó khi khởi động (`configure_logging`).

Backend (`backend/`) và `engine_manager/`: xem mục trạng thái ở đầu file (Phase 3 bước A, B). Sync SQLAlchemy 2 + psycopg 3 trên PostgreSQL, endpoint viết `def` (FastAPI chạy trong threadpool); không dùng async.

Engine C (`engine/`): `Makefile` (`DS_SRCS` = `src/*.c`, theo dõi header bằng `-MMD`); phần DeepStream ở `src/` gồm **bảy module** (tách ngày 2026-11-08, xem bullet "tách `ds_engine.c`" ở đầu file): `ds_engine.c` (`build_pipeline`, bus, tín hiệu, `main`), `app.h` (`SourceCtx`, `AppCtx`, `make_element`), `config.c/.h` (CLI + file camera + cài đặt theo camera), `sources.c/.h` (ô camera, thêm/gỡ lúc chạy, `on_reload`, phát hiện mất RTSP), `probes.c/.h` (`settings_probe`, `detection_probe`, snapshot, đẩy hàng đợi), `delivery.c/.h` (thread `publisher`: file snapshot, HTTP, spool), `stream_out.c/.h` (nhánh mã hóa + publisher RTMP), `report.c/.h` (thống kê, FPS, heartbeat); `src/core/` (C thuần, test được trên host: `detection.h/.c`, `event_manager.h/.c`, `event_record.h/.c`, `event_spool.h/.c`, `backoff.h/.c`, `heartbeat_record.h/.c`); `configs/` (`pgie_yolov8n.txt`, `tracker_nvdcf.yml`, `labels.txt`, `pgie_sample.txt` smoke test); `parser/` (parser bbox YOLOv8 bằng C++); `tools/export_yolov8_onnx.py`, `tools/fake_receiver.py` (backend giả để test publisher), `tools/rtsp_test_server.c` (camera RTSP giả để test reconnect); `models/` (ONNX + engine, gitignore); `tests/` (`test_runner.c`, `test_detection.c`, `test_event_manager.c` chạy vector chung, `test_event_record.c`, `test_event_spool.c`, `test_heartbeat_record.c`, `json_mini.*`, `test_util.h`: 29 test C).

`data/snapshots/`, `data/videos/` và `logs/` đều bị gitignore trừ file `.gitkeep`; video test cục bộ đặt
trong `data/videos/`.

## Định hướng phát triển (đang triển khai)

**`ROADMAP.md` (ở thư mục gốc, gitignored, cá nhân) là kế hoạch phát triển chính của dự án — đọc nó trước khi làm
bất kỳ việc nào liên quan đến DeepStream, backend, frontend hay streaming, và bám theo nó** (thứ tự Phase, quyết định
kỹ thuật ở mục 4, các quy tắc ở mục 5, Definition of Done). Nếu thấy roadmap mâu thuẫn với code thực tế hoặc không
hợp lý, nói rõ cho chủ repo thay vì tự đổi hướng. Mọi mô tả ở các mục trên vẫn là hiện trạng thực tế; **chưa có**
`frontend/` trong repo (`backend/` đã có phần nền, xem Phase 3 bước A); `engine/` đã xong Phase 1 (pipeline N nguồn + YOLOv8n + NvDCF + video debug chạy được, xem mục trạng thái ở
đầu file). Khi làm theo roadmap:

- Làm tuần tự theo Phase; các mục `[CẦN XÁC MINH]` trong roadmap phải được kiểm chứng (tài liệu NVIDIA hoặc chạy
  thử) trước khi dựa vào, không tự suy đoán.
- **Engine DeepStream viết bằng C** (GStreamer + DeepStream C API, pad probe bằng C), build bằng **Makefile** trong
  DeepStream container (theo mẫu `deepstream-test1`, cần `CUDA_VER=12.6`). **Không dùng Python/`pyds`** cho pipeline
  hay probe, và không dựa vào Python sample của DeepStream. Python chỉ xuất hiện ở 3 chỗ: Backend (FastAPI), Engine
  Manager (giám sát process, không chạm DeepStream) và công cụ offline/test (export ONNX, receiver giả, benchmark) —
  không bao giờ nằm giữa đường xử lý frame.
- **Phần DeepStream của engine nằm ở `engine/src/*.c`** (bảy module, xem mục trạng thái), tự viết theo cấu trúc của
  `deepstream_test3_app.c`. Ban đầu là MỘT file `ds_engine.c`; chủ repo yêu cầu tách ngày 2026-11-08 vì file đã dài 2528 dòng.
  Không tách thêm khi chủ repo chưa yêu cầu. Quy ước khi thêm code: hàm dùng chung giữa module khai báo trong header của module đó, hàm
  chỉ dùng trong một module thì `static`; tùy chọn dòng lệnh là biến toàn cục `opt_*` trong `config.c` (chỉ đọc sau `config_load`). Sample là
  `LicenseRef-NvidiaProprietary`: chỉ đọc để học, không chép nguyên văn vào repo. Phần C thuần không phụ thuộc DeepStream vẫn nằm ở
  `engine/src/core/` để `make test-core` chạy được trên host.
- **Kiến trúc engine: 1 process = 1 pipeline = N camera** (`nvstreammux` gom N nguồn thành 1 batch), không phải 1
  process/camera. Mọi code chạy với N = 1 qua đường code chung với N > 1, không có bản "1 camera" riêng. Trạng thái
  theo từng nguồn (EventManager, FPS, state RECONNECTING) nằm trong mảng theo `source_id`; `track_id` chỉ duy nhất
  trong từng source nên khoá là `(source_id, track_id)`, `camera_id` chỉ tra từ `source_id` khi dựng event; lỗi/EOS
  của 1 nguồn không được dừng cả pipeline khi còn nguồn khác. Probe gắn **trước** tiler/demux (khi batch còn
  nguyên). Điểm xuất phát: các sample C có sẵn trong image DeepStream (`deepstream-test1`, `deepstream-test3` nhiều
  nguồn, `deepstream-image-meta-test`). Model: ONNX tự export từ `yolov8n.pt` (`engine/tools/export_yolov8_onnx.py`, dynamic batch),
  engine TensorRT FP16 do `nvinfer` build và lưu ở `engine/models/` (gitignore), parser bbox tự viết ở `engine/parser/`.
- Engine C không import được code Python: `EventManager` được port sang C (`engine/src/core/`, C thuần để test được
  trên host bằng `make test-core`). `src/events/person_detected.py` là **đặc tả chuẩn**; hai bản phải pass chung bộ
  test vector `tests/vectors/`.
- 34 test pytest cũ (cùng 16 test vector) phải luôn xanh, không sửa test cũ để cho qua. Chỉ thêm field tùy chọn có default vào `PersonDetectedEvent`.
- Pad probe không được block: không gọi mạng/Telegram/ghi đĩa nặng trong probe; probe chỉ copy giá trị từ
  `NvDs*Meta` ra struct riêng rồi đẩy sang hàng đợi/worker. Telegram chỉ do Backend gửi. Thời gian logic dựa trên
  `stream_start[source_id] + PTS`, không dùng giờ tường.
- Mật khẩu RTSP không để trong argv của engine (lộ qua `ps`): dùng `--cameras-file` (quyền 600; engine từ chối file có quyền group/others).
- Hệ thống chỉ chạy trong LAN, chưa cần auth (đã chốt); auth chỉ bắt buộc nếu sau này mở ra ngoài LAN.
- Không lộ credential: không log nguyên RTSP URL hay token Telegram.
- Sau mỗi phase hoàn tất, cập nhật `CLAUDE.md`, `README.md` **và `HOC_DU_AN.md`** cho khớp mã nguồn.
